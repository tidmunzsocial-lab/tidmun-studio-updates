# ข้อตกลงการทำงานของ SnapGen, GPT และ Tailscale

> เอกสารนี้เป็น Developer Note ไม่แสดงในหน้าจอโปรแกรม

## เป้าหมายที่เจ้าของโปรแกรมกำหนด

คอมพิวเตอร์ของสมาชิกแต่ละคนต้องทำงานของตัวเอง:

```text
เครื่องทีม A: SnapGen A → Bridge A ในเครื่อง → GPT บัญชีกลาง
เครื่องทีม B: SnapGen B → Bridge B ในเครื่อง → GPT บัญชีกลาง
เครื่องทีม C: SnapGen C → Bridge C ในเครื่อง → GPT บัญชีกลาง
```

ทุกเครื่องใช้:

- โปรแกรม SnapGen ของเครื่องตัวเอง
- Bridge ที่รันอยู่ภายในเครื่องตัวเอง
- GPT บัญชีเดียวกัน
- Tailscale บัญชีหรือ Tailnet เดียวกัน

## สิ่งที่ห้ามตีความผิด

- ไม่มีเครื่องหลักหรือ Central Bridge
- ห้ามบังคับให้เครื่องทีมส่งงานไปยัง Bridge ของเครื่องอื่น
- ห้ามใช้ Tailscale Serve เพื่อรวม GPT requests ไปที่เครื่องเดียว
- ห้ามเปิด Bridge ให้เครื่องอื่นเชื่อมต่อโดยตรง
- Tailscale และ GPT ใช้บัญชีร่วมกัน แต่ Bridge ยังแยกเครื่องใครเครื่องมัน

## เหตุผลที่ Bridge ใช้ 127.0.0.1

Bridge ของแต่ละเครื่องฟังที่:

```text
127.0.0.1:8000
```

`127.0.0.1` หมายถึง SnapGen ติดต่อ Bridge ภายในคอมเครื่องเดียวกันเท่านั้น
นี่เป็นพฤติกรรมที่ถูกต้องตามสถาปัตยกรรมของโปรแกรม

Tailscale ไม่ได้อยู่ระหว่าง SnapGen กับ GPT:

```text
SnapGen → Tailscale → Bridge
```

รูปด้านบนเป็นรูปแบบที่ผิดสำหรับโปรแกรมนี้

รูปแบบที่ถูกต้องคือ:

```text
SnapGen → Bridge ในเครื่องเดียวกัน → GPT บัญชีเดียวกับทีม
```

ส่วนทุกเครื่องยังคงล็อกอิน Tailscale บัญชี/เครือข่ายเดียวกันสำหรับงานของ
Tailscale ที่โปรแกรมต้องใช้ แต่ไม่ใช้เป็นทางส่ง GPT requests ไปยัง Bridge กลาง

## ข้อกำหนดสำหรับการแก้โปรแกรมในอนาคต

1. ทุกเครื่องต้องเปิดและซ่อม Bridge ของตัวเองได้
2. ทุกหน้าต้องติดต่อ Bridge ที่ `127.0.0.1` ของเครื่องนั้น
3. การตั้งค่าหรือ Restore ต้องไม่เปลี่ยนไปใช้ Central Bridge
4. ห้ามเปลี่ยน `127.0.0.1` เป็น `0.0.0.0` โดยไม่มีเหตุผลใหม่จากเจ้าของโปรแกรม
5. ก่อนแก้ระบบ Bridge, GPT account หรือ Tailscale ต้องอ่านเอกสารนี้ก่อน
