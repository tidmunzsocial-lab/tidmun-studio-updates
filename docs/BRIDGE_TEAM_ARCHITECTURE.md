# ข้อตกลงโครงสร้าง Bridge สำหรับทีม

> เอกสารนี้เป็น Developer Note ไม่แสดงในหน้าจอโปรแกรม

## เป้าหมายที่เจ้าของโปรแกรมกำหนด

SnapGen ต้องรองรับการใช้งานแบบ “หนึ่งเครื่องหลักเหมือนเป็นเครื่องเดียวกัน”:

```text
เครื่องของสมาชิกทีมหลายเครื่อง
        ↓
เครือข่ายส่วนตัว Tailscale
        ↓
Bridge บนเครื่องหลักหนึ่งเครื่อง
        ↓
บัญชี GPT และ session ที่อยู่บนเครื่องหลัก
```

สมาชิกทีมทุกคนต้องสามารถส่งงานผ่าน Bridge กลางได้ โดยไม่ต้องเปิด Bridge
หรือเพิ่มบัญชี GPT แยกบนเครื่องของตัวเอง

## สิ่งที่ห้ามตีความผิด

- ห้ามสรุปว่าแต่ละเครื่องต้องใช้ Bridge ของตัวเอง
- ห้ามเปลี่ยนระบบให้เป็น local-only ถาวรเพียงเพราะ Bridge ฟังที่ `127.0.0.1`
- ห้ามเปิด Bridge ตรงสู่ Wi-Fi/LAN หรืออินเทอร์เน็ตโดยไม่มีการควบคุม
- ห้ามใช้ Tailscale Funnel เพราะระบบนี้ไม่ได้ต้องการเปิดให้บุคคลทั่วไป

## รูปแบบที่ตั้งใจใช้

Bridge บนเครื่องหลักฟังที่:

```text
127.0.0.1:8000
```

จากนั้นใช้ Tailscale Serve เป็นทางเข้าของทีม:

```bat
tailscale serve --bg --tcp=8000 tcp://127.0.0.1:8000
```

เครื่องสมาชิกติดต่อผ่านชื่อ MagicDNS หรือ Tailscale IP ของเครื่องหลัก เช่น:

```text
http://ชื่อเครื่องหลัก:8000/v1
```

## งานที่โปรแกรมต้องรองรับ

1. โหมดเครื่องหลัก: เปิด Bridge และเก็บบัญชี GPT
2. โหมดเครื่องทีม: ไม่เปิด Bridge เอง แต่ติดต่อเครื่องหลักผ่าน Tailscale
3. ตั้งชื่อเครื่องหลักหรือ URL กลางได้จากค่าตั้งค่าเดียว
4. ทุกหน้า Image, Video, Ref, Story/Face, Prop และ Karaoke ต้องใช้ URL กลางเดียวกัน
5. หากเครื่องหลักหรือ Tailscale ติดต่อไม่ได้ ต้องแจ้งสาเหตุให้ผู้ใช้ทราบ
6. การเปลี่ยนแปลงระบบ Bridge ในอนาคตต้องอ่านเอกสารนี้ก่อน

## เหตุผลที่ยังให้ Bridge ฟังที่ 127.0.0.1

การฟังที่ `127.0.0.1` ป้องกันไม่ให้คนใน Wi-Fi/LAN เข้าถึง Bridge โดยตรง
Tailscale Serve จะเป็นผู้รับการเชื่อมต่อจากสมาชิกทีมที่ได้รับอนุญาต แล้วส่งต่อ
เข้า Bridge ภายในเครื่องหลักอีกทอดหนึ่ง
